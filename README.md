# STM32 独立看门狗（IWDG）实验

基于 STM32F103C8T6 的独立看门狗实验，配套江协科技 STM32 入门教程（第 14 章）。

## 功能

- 独立看门狗 IWDG，超时约 **1 秒**（LSI 40kHz ÷ 16，重装值 2499）
- 主循环持续喂狗，程序正常时不会复位
- 按下 KEY1 模拟“程序卡死”（死循环、不喂狗），约 1 秒后看门狗复位
- OLED 显示两个按键引脚电平，便于排查接线

## 超时时间计算

```
LSI ≈ 40kHz
预分频 16      → 40kHz / 16 = 2.5kHz（每 0.4ms 计一次）
重装值 2499    → (2499 + 1) × 0.4ms ≈ 1 秒
```

> LSI 实际频率在 30–60kHz 之间波动，真实超时约 0.7–1.3 秒，属于正常现象。

## 硬件接线

| STM32 引脚 | 功能 | 说明 |
|---|---|---|
| PB1 | KEY1 | 按键另一端接 GND，内部上拉 |
| PB11 | KEY2 | 同上 |
| PB8 / PB9 | 软件 I2C | OLED 显示屏 |

**按键接法要点**：轻触按键要**跨面包板中间凹槽**插；四脚按键取**不同侧**的两个脚。
同侧插会让引脚直接接地，读出来恒为 0。

## 代码要点

**初始化顺序**（`IWDG_Enable()` 之前必须先写入重装值）

```c
IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);
IWDG_SetPrescaler(IWDG_Prescaler_16);
IWDG_SetReload(2499);
IWDG_ReloadCounter();
IWDG_Enable();
```

**喂狗**

```c
IWDG_ReloadCounter();
```

## 调试记录：STOP 反复闪、FEED 永远不出现

**现象**：上电后 OLED 反复显示 `STOP`，从不进入主循环的 `FEED`，板子约每 1 秒复位一次。

**排查过程**：

1. 现象是“反复复位”，说明程序在某处停住，超过 1 秒没喂狗
2. 读按键引脚电平，发现**接上按键后 PB1 恒为 0**（松开也是 0）
3. `Key_GetNum()` 内部有 `while (引脚 == 0);`（等待松手），引脚恒 0 时**永远不返回**
4. 于是 `IWDG_ReloadCounter()` 执行不到 → 看门狗复位 → 重启后再次卡在同一处 → 循环

**两个原因**：

| 原因 | 说明 |
|---|---|
| 漏调 `Key_Init()` | GPIOB 时钟未开，读引脚恒为 0，同样卡在等待松手 |
| 按键插法错误 | 四脚按键同侧插入，或两脚按键平行插在同一行，引脚被直接接地 |

**修复**：

- 补上 `Key_Init()`
- 按键跨面包板凹槽插，确保两个脚落在互不连通的两行
- 排查时用 OLED 显示 `GPIO_ReadInputDataBit()` 的值：`1 1` 正常，`0 1` / `1 0` 说明对应引脚被拉低

**教训**：

> 外设不响应时，先读它的输入状态（GPIO 电平、寄存器），比反复换线快得多。
> 看门狗项目里任何阻塞调用（如等待松手的按键扫描）都可能导致复位循环。
